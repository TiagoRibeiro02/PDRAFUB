# ZeroID KYC Compliance System

This document explains how to set up and use the Zero-Knowledge Proof (ZKP) based KYC/AML compliance system for DIDs linked to NFTs.

## Overview

The system consists of:

1. **PlonkVerifier** - Verifies zero-knowledge proofs generated using PLONK
2. **PlonkVerifierAdapter** - Adapts the verifier to work with flexible input types
3. **KYCCompliance** - Main contract that stores and verifies KYC/AML compliance status

## Architecture

```
┌─────────────────────┐
│   ZKP Issuer UI     │  Generate ZK proofs for DIDs
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│  KYCCompliance.sol  │  Verify & store compliance status
└──────────┬──────────┘
           │ uses
           ▼
┌─────────────────────┐
│PlonkVerifierAdapter │  Adapts proof format
└──────────┬──────────┘
           │ uses
           ▼
┌─────────────────────┐
│  PlonkVerifier.sol  │  Cryptographic verification
└─────────────────────┘
```

## Setup Instructions

### 1. Prerequisites

- Hardhat node running on localhost:8545
- MetaMask connected to localhost network (Chain ID: 1337)

### 2. Deploy NFT Contract (if not already done)

```bash
cd nfts
npm install
npm run deploy
```

This deploys the MyNFT contract and saves the address to `artifacts/contract-address.json`.

### 3. Deploy KYC Compliance Contracts

```bash
npm run deploy:kyc
```

This will:
- Deploy PlonkVerifierAdapter
- Deploy KYCCompliance contract
- Save contract addresses to:
  - `nfts/artifacts/kyc-deployment.json`
  - `zeroid-entity/src/contracts/kyc-deployment.json`
- Copy ABIs to `zeroid-entity/src/contracts/`

### 4. Start the Entity Application

```bash
cd ../zeroid-entity
npm install
npm run dev
```

Open http://localhost:5173 in your browser.

## How It Works

### For Bank/Issuer (Entity Side)

1. **Navigate to "ZK Proof Issuer" tab**
2. **Enter a user's DID** (e.g., `did:zeroid:user123`)
3. **Click "Generate PLONK ZK Proof"**
   - This generates a zero-knowledge proof that proves the user is KYC/AML compliant
   - The proof doesn't reveal any personal information
4. **Click "Submit to Blockchain"**
   - The proof is verified on-chain
   - If valid, the DID is marked as compliant in the KYCCompliance contract
   - A timestamp and commitment are stored

### For Users (NFT Bank View)

1. **View "Purchased NFTs" section**
2. **Each NFT card shows:**
   - NFT image and details
   - Owner's DID
   - **✅ KYC/AML Compliance Badge**
     - Green checkmark if compliant
     - Warning icon if not verified
     - Verification timestamp

## Smart Contract Functions

### KYCCompliance Contract

#### `submitComplianceProof(did, commitment, proof, publicSignals)`
- Submits a ZK proof to verify KYC/AML compliance
- Only callable by the issuer
- Verifies the proof using PlonkVerifier
- Stores compliance status if valid

#### `checkCompliance(did) → (isCompliant, timestamp, commitment)`
- Returns full compliance information for a DID
- Public function - anyone can check

#### `isCompliant(did) → bool`
- Returns simple boolean compliance status
- Public function

#### `revokeCompliance(did)`
- Removes compliance status for a DID
- Only callable by issuer
- Use in case of compliance issues

## Security Features

1. **Zero-Knowledge Proofs**: User privacy is protected - no personal data is revealed
2. **On-Chain Verification**: All proofs are cryptographically verified on the blockchain
3. **Issuer Control**: Only authorized issuers can submit compliance proofs
4. **Public Verification**: Anyone can check if a DID is compliant
5. **Immutable Records**: Compliance records are stored on the blockchain with timestamps

## Example Flow

```
1. User completes KYC with Bank
   └─> Bank verifies identity (off-chain)

2. Bank generates ZK Proof
   └─> Proof shows: "User is KYC compliant"
   └─> Without revealing: user's name, address, etc.

3. Bank submits proof to blockchain
   └─> Smart contract verifies proof
   └─> DID marked as compliant

4. Anyone viewing the NFT can see:
   └─> ✅ This DID is KYC/AML compliant
   └─> Verified on: [date]
```

## Troubleshooting

### "KYC contract not deployed" error
- Run `npm run deploy:kyc` from the nfts directory
- Ensure Hardhat node is running
- Check that contract files exist in `zeroid-entity/src/contracts/`

### Proof verification fails
- Ensure the circuit files (circuit.wasm, circuit_final.zkey) are in the public folder
- Check that the verification_key.json matches the circuit
- Verify the PlonkVerifier.sol is correctly generated

### Compliance badge not showing
- Ensure KYC contract is deployed
- Check that a proof was successfully submitted for the DID
- Open browser console to check for errors

## API Reference

### Frontend Functions

#### `generatePlonkZKP(userDid: string)`
Generates a zero-knowledge proof for a DID.

**Returns:** `{ proof, publicSignals, commitment }`

#### `submitProofToContract(userDid: string, zkProof: any)`
Submits a proof to the KYCCompliance smart contract.

**Throws:** Error if submission fails

#### `checkComplianceForDIDs(dids: string[], nfts: NFTListing[])`
Batch checks compliance status for multiple DIDs.

Updates NFT listings with compliance info.
